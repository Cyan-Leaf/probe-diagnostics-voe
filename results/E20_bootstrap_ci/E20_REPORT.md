# E20 — 主结论的聚类 bootstrap 置信区间

> 执行于 2026-11-05，纯 CPU。**设计冻结于 `E20_PREREG.md`**（写在任何区间算出之前）。
> 原始数据：`E20_cells.json` / `E20_verdict.json` / `E20_arms.journal.jsonl`。
> 脚本：`e20_bootstrap_ci.py`。

## 0. 一句话结论

**D2 的 12 个格全部稳健（区间不含 0）；D1 有 3 个格判定脆弱，且全部贴着 50% 阈值。**

这是本项目第一次给主结论配误差条。它没有推翻任何判定，但把「哪些判定经得起重采样」
和「哪些是这一次抽样的巧合」第一次分开了。

## 1. 为什么需要这一步

此前 `D1_TALLY.json`（35 格）与 `D2_TALLY.json`（34 格）**只有点估计，一个区间都没有**，
而 `PREREG.md` 从未规定过。三条已有结果说明这不够：

- **E16** 测得 probe 划分的 sd 为 **2.51 pp**；
- **E18** 在弱信号区测得 feature seed 的 sd 高达 **20–26 pp**；
- **E18** 还发现一个 0.0116 的 AUC 差能变成约 10 pp 的 D1 ——
  因为 D1 是**比值**，而分母 `AUC_real − 0.5` 曾低到 0.096。

比值没有点估计能表达的误差结构。而全表最小 D2 gap 只有 **+0.0428**，
两个 D1 格距阈值不到 2 pp —— 这些数此前无法判断是模型性质还是抽样波动。

## 2. 方法（含一处必须如实登记的偏离）

设计见 `E20_PREREG.md`。**关键偏离：预注册 §2/§3 写的是「每次抽样重拟合 probe」，
实测不可行，改为「折外分数 bootstrap」。**

| | 预注册写法 | 实际做法 |
|---|---|---|
| 拟合次数 | 每 draw 重拟合（36 格 × 300 = 10800 次） | **每格每个 seed 拟合一次**（54 次） |
| 抽样作用对象 | 重拟合后重算 | **折外（out-of-fold）决策分数** |
| 实测耗时 | 单次拟合 13–30 s → **数十小时**（且 64 worker 并行时退化到 150 s+/次） | **6.8 分钟** |

**代价，必须写清**：区间**条件于已拟合的模型**，只度量**评估集**的抽样变异，
**不含重新拟合分类器的额外变异**。因此它比完整的重拟合 bootstrap **略窄**。
被漏掉的那部分量级可由 E16 的 2.51 pp 参考。
**替代方案是干脆不报区间** —— 选择前者，但把这个限制写在报告里而不是省略。

其余设计未变，且都写死：

1. **按聚类（scene / subgroup）重采样，绝不按行** —— 两个 probe 都用 group-disjoint CV，
   按行重采样会让同一场景同时出现在折内外。
2. **配对**：一次抽样内，一个格的所有臂用**同一组聚类**；区间取自**合成量**
   （D1 是比值、D2 是差值），**不是**两条边缘区间。
3. 重复抽到的聚类**保留原 id**。
4. **百分位 95% 区间，B = 300**，不做 BCa。

D1 的分母**从 `e8_verdict.d1_ratio` 导入，不重写** —— 见 §5 的错误记录。

## 4. 三个脆弱格意味着什么

| 格 | 问题 |
|---|---|
| **LTX @ IntPhys 2** | 区间宽达 **52 pp** [24.06, 76.08]，跨过阈值。它本来就是 `D1_TALLY` 里唯一的 `NOT interpretable`（E8 的 2× 地板判据拒绝了这个比值）。E20 独立地得出同一结论：**这一格不可解读**，点估计 50.24% 的 "pass" 不应被引用。 |
| **CogVideoX-2b @ LikePhys** | 点 44.86%，区间上界 54.06%，**跨过 50%**。 |
| **CogVideoX-5b @ LikePhys** | 点 43.79%，区间上界 51.75%，**跨过 50%**。 |

**后两个是真正的新信息**：它们此前被报作确定的 `fail`（42.65% / 43.49%），
但按 E20 的区间，**「训练贡献少于一半」这个判定在这两格上不能与「恰好一半」区分**。
`D1_TALLY.json` 里的 fail **不撤回**（改已交付判定是禁止的），但任何引用这两格的句子
必须同时给出区间。

注意这与 E16 的发现一致且有独立价值：E16 变的是 probe 划分（2.51 pp 量级），
E20 变的是**评估集里有哪些场景**（区间宽度 7–52 pp）。**场景抽样是更大的一项误差来源。**

## 5. 过程中的三个错误（全部如实登记）

**错误 1：D1 分母写错。** 首次实现用了 `(AUC_real − AUC_random) / AUC_real`，
而 E8 的定义是 `(AUC_real − AUC_random) / (AUC_real − 0.5)`。
后果：全部 12 格 D1 被压到 1–26%，看起来像「D1 全面 fail」，
与 `D1_TALLY` 的 24/25 pass 直接矛盾 —— 是这个矛盾暴露了错误。
**修法：从 `e8_verdict.d1_ratio` 导入，不再自己写分母。**

**错误 2：只用了 seed 0。** E8 的 `d1_pct` 是 **3 个 feature seed 的均值**。
单 seed 差异可达 **30 pp**（LTX：48.47% vs seed-0 的 18.08%）。
**修法：改为 3 seed 均值，与交付口径一致。**

**错误 3：预注册的「每次重拟合」不可行。** 实测单次拟合 13–30 s，
10800 次需数十小时；64 worker 并行时因 BLAS 线程超订退化到 150 s+/次。
**改用折外分数 bootstrap，代价写在 §2。**

## 6. 自检（PREREG §6，逐条给结果）

1. **折外池化 AUC vs `probe()` AUC**：逐臂比对，差异 **1e-5 … 1.2e-2**。
   最大者出现在 `wan21_14b|intphys2|real`（+5.4e-3）与 `random`（+1.2e-2）。
   这是「池化分数」与「逐折平均 AUC」的固有差别，**不是**实现错误，逐格记录在
   `E20_cells.json.self_check`。
2. **恒等展开**：设计阶段实测重排行序会带来 1.9e-05（IntPhys 2）／3.4e-04（LikePhys）
   的 AUC 变化 —— 根因是 `StandardScaler` 的浮点求和顺序（scale 最大差 7.1e-15），
   经 `_rowspace` 的近零方向放大。**这条本身是个发现：冻结的 probe 对行序敏感至 1e-4 AUC。**
   容差据此设为 1e-3。
3. **蒙特卡洛稳定性**：把 300 次抽样拆成两半分别取区间，端点分歧占区间宽度的比例
   **0.01 … 0.16**（逐格记录）。B=300 足够。

## 7. 局限

1. **区间不含重拟合变异**（§2）。E16 的 2.51 pp 是该成分的量级参考。
2. **覆盖范围只有 E8 的 6 族 × 2 数据集 × L16**，不含 E13/E14/E15/E17/E18/E19 的新增模型，
   也不含 `Lrel` 层。理由见 PREREG §5（这 12 格已覆盖 D2 gap 从 +0.0428 到 +0.4388 的全区间）。
3. **LTX @ IntPhys 2 的区间宽到 52 pp**，说明该格的比值统计量本身不稳 ——
   这与 E8 判它 `NOT interpretable` 是同一件事的两个侧面，不是两个独立发现。
4. **`intphys2` 的 `cj` 臂与 `real` 臂共享同一批 Possible clip**，两臂的抽样误差相关。
   配对抽样已正确处理这一点（同一 draw 用同一组聚类），但这也意味着
   D2 区间的宽度不能解读为「两个独立测量的差」。

