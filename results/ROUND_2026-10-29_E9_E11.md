## 1. E9：饱和场景的偏差被量化了，而且它不重要

### 1.1 结果

| 总体量 | 全部 clip | 剔除饱和后 | Δ |
|---|---|---|---|
| **池化 D1**（E8 口径）| 32.90% | **35.83%** | **+2.93 pp** |
| real / random AUC | 0.9389 / 0.7945 | 0.9273 / 0.7742 | — |
| 样本量 | 750 clip | 630 clip（−16.0%）| — |
| **逐场景 D1 均值** | 15.40%（n=11）| **18.83%**（n=9）| +3.43 pp |

**两个总体量同向上升，幅度都是个位百分点。** 预注册担心的情形（剔除后越过 50%）没有发生。

**自检**：全部 clip 的池化 D1 = 32.898%，**逐位等于 E8 交付的 32.9%**，说明复用
`e8_analyse.probe` 是有效的。

### 1.2 三个必须写进 Limitations 的发现

**(a) "5 个饱和场景"这个数在这个格上复现不出来 —— 实际是 2 个。**

`NEXT_STEPS_AND_DIVISION.md` §1 写的是「12 场景中 5 个 `real−random=0`」。
按预注册定义（两臂都 `≥ 1.000 − 1e-9`）在 L16/t=600 上数：

| 口径 | n |
|---|---|
| 两臂都到 1.000 | **2**（`cloth_drape`, `fluid`）|
| 只有 real 臂到 1.000 | 8 |
| 差值恰为 0.00 | **2** |

而 `EXPERIMENTS.md` §5.6 的 D3 = **5/12** 是在 **L14 / t=400** 上算的，
**那个格的特征不在缓存里**（`load_X` 对 L14/t=400 返回 `None`），所以**无法在这台机器上重算**。

→ 登记为 **`not_reproduced_and_not_refuted`**。**不能用 2 去改 5，也不能当 5 已被验证。**
→ 附带结论：**"饱和场景数"随 (层, timestep) 变**，任何引用都必须带格。

**(b) `shadow_camera` 的 real AUC = 0.3662，低于随机猜测。**

这不是"训练贡献小"，是**训练后判反了**。归档材料记录过这个场景（唯一带相机运动的）
曾掉到 0.500，E9 测得 0.3662 —— 同方向、更差。**E9 只测量、未解释。**

因为 `AUC_real < 0.5`，D1 的分母是负的，这个值**未定义**而不是很小。
处理方式：**从两侧的逐场景均值中都剔除**，并显式记录（`undefined_scenarios`）。

**(c) 真正的问题不是饱和，是场景之间差 60 多个百分点。**

| 场景 | D1 |
|---|---|
| `ball_collision` | **63.82%** |
| `block_slide` | 40.55% |
| `pendulum` | 39.20% |
| `flag` / `river` | 12.22% / 10.19% |
| `faucet` / `pyramid` / `ball_drop` | 2.98% / 2.50% / 1.04% |
| `cloth_drape` / `fluid` | 0.00%（饱和）|
| `shadow` | **−3.05%** |
| `shadow_camera` | 未定义（0.3662）|

**全局 32.90% 落在这个区间的中部，是个没有代表性的均值。**
→ **LikePhys 不是一个任务，是 12 个难度不同的任务。** 每个分量只有 50–80 个 clip。
这条比 E9 的原问题更重要，应写进 Limitations。

### 1.3 Q2 的 +2.93 pp 怎么读

`|Δ| = 2.93 > 2.51`（E16 的 probe 划分 sd），**超了噪声线**，所以不能说"在噪声内"。

但：
1. **方向符合预注册预测**（剔除饱和 → 分子变大、分母变小 → D1 上升）。
2. **归因不干净**：剔除 120 个 clip 同时改变了 group 集合，也就改变了 CV 折划分。
   所以这 2.93 pp 里有多少来自"去掉饱和"、多少来自"换了折"，**本设计分不开**。

→ 正确表述：**这是"剔除饱和场景"这一操作的总效应（含换折），方向正确、量级小、不足以改变判定。**

## 2. E11：更强的非线性读出不会翻盘

### 2.1 结果

| 格 | 线性（基准）| Nyström（最强合格）| Δ | 判定 |
|---|---|---|---|---|
| Wan2.1-1.3B @ LikePhys | 32.90% | **25.28%** | −7.62 pp | robust |
| HunyuanVideo @ LikePhys | 27.01% | **35.11%** | +8.10 pp | robust |
| V-JEPA 2 @ LikePhys | 49.36% | **45.16%** | −4.20 pp | robust |
| Wan2.1-1.3B @ IntPhys 2 | 91.21% | **85.87%** | −5.34 pp | robust |

**每一格的最强合格读出都和线性档落在 50% 的同一侧。**

**自检通过**：线性档逐位复现 E8 的交付值（32.90 / 27.01 / 49.36 / 91.21 vs
32.9 / 27.0 / 49.4 / 91.2）。

### 2.2 本轮最重要的方法学产出：`random` 臂塌陷会把 D1 推高

前置门槛（Q2：读出不得比线性档低超过 0.01 AUC）**把 MLP 全部拒收了**：

| 格 | MLP AUC 比线性低 | MLP real / random | 线性 real / random |
|---|---|---|---|
| Wan2.1-1.3B @ LikePhys | −0.0324 | 0.9065 / **0.5937** | 0.9389 / 0.7945 |
| HunyuanVideo @ LikePhys | −0.0318 | 0.9107 / **0.5547** | 0.9425 / 0.8230 |
| V-JEPA 2 @ LikePhys | −0.0358 | 0.9411 / **0.5959** | 0.9769 / 0.7332 |
| Wan2.1-1.3B @ IntPhys 2 | **−0.1271** | 0.5230 / **0.5026** | 0.6502 / 0.5132 |

**MLP 的 D1 看起来非常"戏剧"：77.0% / 86.7% / 78.3% / 88.7%。** 那是假的：

- `random` 臂被砸到 0.50–0.60，`real` 臂只掉 0.03
- **分母（real − 0.5）塌得比分子快** → D1 被机械推高
- 最极端那格：MLP 的 `random` = 0.5026（几乎抛硬币），分母只剩 0.023

**⚠️ 措辞纪律（重要）**：MLP 的 `unconverged_folds = 0`，四格全部收敛。
所以**不能**写"优化没收敛"或"欠拟合"。正确的描述是
**在 n≈750 上过拟合/泛化失败** —— 这是**估计问题**，不是**优化问题**。

旧 `EXPERIMENTS.md` §5.3.2 差点掉进同一个坑（它的 MLP 也把 D1 从 28.5% 推到 43.9%），
只是没跨阈值所以没被发现。

### 2.3 V-JEPA 那一格必须用 6 划分均值

V-JEPA 在 LikePhys 上的 D1 **不是单点数**（E15/E16 已证它在 43.8–54.0% 间摆动）。

| 读出 | 6 划分均值 | sd | 低于 50% 的划分 |
|---|---|---|---|
| 线性 | **49.36%** | 2.25 | 5/6 |
| Nyström | **45.16%** | 3.70 | 5/6 |

**若用 seed 1000 的单点（51.11%），连 E8 交付的 49.4% 都复现不了**，三档比较就失效。
数据见 `E11_vjepa_probe_seeds.json`。

### 2.4 仍未被封死的退路

**只测了 Nyström 一种非线性家族，且只有 4 个格。**
真正的最强读出（temporal attention probe，Punzo 那类）**未测**。
→ 写 Limitations 时必须保留这一条，**不能**说"更强读出已被完全排除"。

## 3. GPU 失效（E18 阻塞）

**4×B200 于 10-29 19:16 全部失效，至今未恢复。**

- `nvidia-smi` 正常（4 卡可见、0% 利用率、ECC 无错、NVLink 8/8 通）
- **CUDA runtime 层挂了**：`cudaGetDeviceCount` 返回 `rc = 999`
- 内核日志：`Xid 154 (GPU lost from the bus)`，8 个 PCI 地址全覆盖，
  `GPU recovery action = 0x2 (Node Reboot Required)`
- 已排除：驱动版本、设备节点、残留进程、ECC、NVLink、multicast 环境变量
- **未做** `nvidia-smi -r`：这是共享多用户机器，且内核已判定需**节点级重启**

→ **需要管理员重启节点。用户态无法恢复。** 完整记录见 `results/GPU_INCIDENT_2026-10-29.md`。

**受影响的任务**：`E18`（把每个专家放回自己的噪声区间）已写好预注册
（`results/E18_own_band/E18_PREREG.md`）但**一格都没跑**。GPU 恢复后可直接开跑：
`e17_extract.py` 已支持 `--t 300/900`，缓存目录带 t 后缀（不污染 E17 交付物）。

## 5. 实现坑（新会话务必先读）

| 坑 | 症状 | 修法 |
|---|---|---|
| **线性 probe 绝不能重写** | 重写版给 30.6%，E8 是 32.9% | 必须 `import e8_analyse.probe` |
| **必须三个 feature seed 取均值** | 单 seed 0 时 `wan21_1b3@IntPhys2` 给 99.5%，E8 是 91.2% | 与 E8 同口径 |
| **V-JEPA 无 feature seed** | `feats["clean"]` 下只有 key `"0"`，按 seed 索引会 `KeyError` | 三 seed 即同一份特征 |
| **V-JEPA 的 D1 不是单点数** | seed 1000 给 51.11%，E8 是 49.4% | 用 6 划分均值 |
| **逐场景均值不能喂 nan** | `shadow_camera` 的 `d1_pct` 是 nan，`np.mean` 会全变 nan | 先把未定义场景从两侧剔除 |
| **场景 mask 必须比单个名字** | 拿场景列表整体比会广播成空 mask，报"剔除 100% 饱和" | 用 `np.flatnonzero(arr == s)` |
| **threads 必须 = 4** | 3 线程偏 0.5pp | 所有 probe 调用 |
