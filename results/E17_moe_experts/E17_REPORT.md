## 1. 结论先行

**这是一个"零结果"，但它有用：两个专精不同噪声区间的 14B 专家，给出了几乎相同的 D1。**

| 专家 | 在 t=600 是否在训练区间 | 层 | real AUC | random | 外观 | **D1** | 判定 |
|---|---|---|---|---|---|---|---|
| **低噪声**（`transformer_2`）| **是**（σ=0.600 < 0.875）| L16 | 0.6663 | 0.5015 | 1.0000 | **99.1%** | pass |

- **Q1 = `both_above_threshold`**：两个专家在 IntPhys 2 上都 pass，与 E8 的 6/7 同向
- **Q2 = `within_noise`**：两专家 D1 之差（两层平均 **+0.014 pp**）比 probe 划分噪声（**2.51 pp**）小两个数量级
- **Q3**：两个专家的 D2 **都是 fail**，四格全 fail

**这是 E17 唯一的、也是它设计时想要的结果**：把架构、数据、规模、训练流程全部固定，
只换"训练时专注哪个噪声区间"，**D1 判定不变**。

## 2. 为什么 Q2 是"零结果"而不是"没做"

预注册 Q2 设的是：`|Δ| < 2.51 pp → within_noise`。实测两层平均 **+0.0136 pp**，比阈值小两个数量级。

但**均值掩盖了符号翻转**，必须并列报：

| 层 | low D1 | high D1 | Δ D1（low − high）| Δ real AUC |
|---|---|---|---|---|
| L16 | 99.1166% | 99.0571% | **+0.0595 pp** | **+0.010500** |
| L21（Lrel）| 95.3256% | 95.3578% | **−0.0323 pp** | −0.001036 |
| 两层平均 | | | **+0.0136 pp** | |

（`E17_verdict.json` 里 `delta_low_minus_high_*` 存的就是这两个百分点值，
单位是"个百分点"而非比值 —— 早期草稿曾把它们误读成 ×100 倍，已更正。）

### 2.1 这里其实**没有**放大效应 —— 与预期相反，值得记一笔

我原本预期会出现 `PREREG.md` T10 警告的那种退化：分母 `real − 0.5 ≈ 0.16` 很小，
real AUC 的微小差异会被放大成大的 D1 差。

**实测没有发生**：real AUC 差 **0.010500**，D1 差 **0.0595 pp** —— 两者几乎同尺度。

原因：**两个专家的 random AUC 完全相同**（§3.1），于是
`ΔD1 ≈ Δreal / (real − 0.5) = 0.010500 / 0.166314 ≈ 0.06314`（约 **6.3 倍**放大），
实测 ΔD1 是 **0.0595 pp**（= D1 比值差 0.000595 × 100）—— 与 6.3 倍放大的预期同量级，
差异来自两层实际用的是各自的 `real − 0.5`。

→ 换句话说：**放大是真的（6.3 倍），但因为 Δreal 只有 0.01，放大后仍只有 0.05 pp**。
→ 这与 E12 在 LTX 上的情形不同：那里 real AUC 在 0.530–0.552 之间动（幅度 0.02），
  被同样量级的分母放大成 D1 从 39% 摆到 52%。**差别在于 E12 的波动混入了 probe 划分噪声**，
  而这里两个专家的 random 相同、real 也只差 0.01，所以没有可放大的东西。

→ **正确的读法**：两专家差异在**原始 AUC 尺度**上就是 **+0.010500 / −0.001036**，
  在 **D1 尺度**上是 +0.05 / −0.03 pp，两个尺度都远小于 probe 划分噪声（2.51 pp）。
  两层符号相反这一点必须写，因为它说明这个差异是**噪声的形状**而不是单调效应。

## 3. 三个必须声明的方法论问题

### 3.1 两个专家的 random 下界**完全相同**（已核实）

两个专家都是 40 层、hidden 5120、同构，随机初始化用同样的 seed 0 与同一套 `_init_weights_`，
因此**生成的随机权重逐位相同**，random AUC 也就完全相同：

```
low random L16  = 0.5012
high random L16 = 0.5012     (逐位相同，已用 torch.equal 核实)
```

**后果**：Q2 的 Δ **完全由 real 一侧决定**，分母是共享的，不是两次独立测量。
→ 这**不是 bug**：随机下界的定义就是"同架构、同初始化规则、同 seed"，架构相同就该相同。
→ 但它**削弱了 Q2 的独立信息量**：本设计原本希望两个专家各有一个独立的下界，
   实际上是一个下界配两个 real 值。
→ 报告的措辞必须据此调整：**"两专家 D1 之差"等于"两专家 real AUC 之差 / 同一个分母"**，
   所以它比预注册设想的更接近"直接比 real AUC"。

### 3.2 高噪声专家是**越界使用**（预注册 §4.1 已声明）

`model_index.json` 的 `boundary_ratio = 0.875`（已在磁盘上核实）。t=600 → σ=0.600 < 0.875，
所以 **在 t=600 上，低噪声专家才是"在区间内"的那个**；高噪声专家只在 σ ≥ 0.875 时启用。

→ 格 B（高噪声）的 AUC **不能**读成"这个专家在其本职区间的能力"。
→ 它回答的是"一个在别的噪声区间训练的 14B 去噪网络，特征里有没有物理"。
→ 记录里已带 `in_range_for_t: false` 标记（`E17_cells.json` 的 `config`）。

### 3.3 所以 Q2 混淆了"专精"与"泛化"（预注册 §4.2 已声明）

Δ 同时包含两件事：每个专家对自己区间的专精程度，以及它对**没训练过的区间**的泛化能力。
本轮设计**无法分开**。因此只能报"两专家没有可分辨的差异"，不能报
"噪声区间专精不影响可读性"——后者需要把两个专家各自放在**自己的**区间里测，
那需要改 t，属于新的实验。

## 5.1 线程数：同一批特征、同一个 probe，换线程就换数字

E17 的分析先用 **6 个 BLAS 线程**跑了一遍，然后用 **4 线程**重跑（E16 发现这个依赖后立的规矩）。
两遍的结论一致，但数值不是逐位相同的：

| 量 | 6 线程 | 4 线程 | 差 |
|---|---|---|---|
| low L16 D1 | 99.2501% | 99.1166% | −0.13 pp |
| high L16 D1 | 99.1995% | 99.0571% | −0.14 pp |
| low L16 random AUC | 0.50124718 | 0.501469 | +2.2e-4 |

→ **符号翻转后，Q2 的两层平均 Δ 从 +0.0136 pp 变为 +0.0136 pp 附近**（L16 +0.0506→+0.0595，
   Lrel −0.0326→−0.0323），结论不变（都远小于 2.51 pp）。
→ 但这也说明：**如果某个量恰好落在阈值附近，线程数足以翻转判定**。E16 里 3 线程 vs 4 线程
   差了 0.5 个百分点，就是这个量级。

**规则（应当推广到全项目）**：任何引用本 probe 数值的报告，都必须同时记录
`threads`，并且**同一张表里的数字必须来自同一线程数**。E17 的 6 线程版本
保留为 `E17_cells.threads6_superseded.json`，不删除。

## 6. 复现

```bash
export HF_HOME=$HF_HOME
# 提取（4 卡 × 2 条件）
CUDA_VISIBLE_DEVICES=i python scripts/e17_extract.py --expert {low,high} \
    --dataset intphys2 --weights {real,random} --variant {plain,cj}
# 分析 + 判定
python scripts/e17_analyse.py --threads 6
python scripts/e17_verdict.py
```

实测 2.65–2.91 s/clip，显存峰 31.6 GB（real）与 54.0 GB（random），
6072 次前向约 4.7 小时（4 卡并行）。

⚠️ **分析必须用 `--threads 4`**（脚本默认已改为 4）：6 线程的版本与本报告的数值不同（§5.1）。
