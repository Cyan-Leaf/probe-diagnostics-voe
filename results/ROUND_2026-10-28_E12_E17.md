# 2026-10-28/29 这一轮：E12–E17 与结论边界

本文记录这一轮做了什么、结论往哪个方向动了、以及**哪些"广泛性"是真的、哪些不是**。

---

## 0. 一句话回答"是不是越来越 solid 和广泛"

**D2 是，而且质量很高。D1 不是——D1 这一轮变窄了，变准了，但没有变广。**

这两件事必须分开说，因为它们是**相反方向的运动**：

| 结论 | 这一轮的方向 | 能否写"广泛" |
|---|---|---|
| **D2**（读出更擅长读编辑痕迹而非物理）| **更广 + 更硬** | ✅ 6 族 11 变体、28 格、含非生成式、零例外 |
| **D1**（训练贡献占比）| **更窄但更准** | ⚠️ 只能写"数据集依赖"，不能写"训练贡献少" |
| 内部**排序**（谁比谁高）| **被否证** | ❌ 差距落在 probe 噪声内，不可写 |

**所以"只需要一些小修正"这个判断，对 D2 成立；对 D1 不成立。**
D1 这一轮动的是**主张本身**，不是措辞。下面逐条说清楚。

## 1. D2 为什么可以写"广泛"

**28 个格、19 个独立单元、6 个模型族、11 个模型变体、2 个数据集、全部 fail，零例外。**

| 轴 | 覆盖范围 |
|---|---|
| 模型族 | Wan / CogVideoX / LTX / Mochi / HunyuanVideo / **V-JEPA 2（非生成式）** |
| 参数量 | 0.33B – 14B |
| 层数 | 24 – 60 |
| block 拓扑 | 单流 / 双流 / **双流→单流串联** / **双专家** / 无 DiT |
| 训练目标 | 去噪（9 变体）+ **JEPA 联合嵌入预测**（2 变体）|
| 加噪形式 | flow matching / VP-DDIM |
| latent 通道 | 12 / 16 / 48 / 128 / 无 VAE |

**为什么这算"广泛"而不是"堆数量"**：每一条新轴上去，都排除了一个具体的替代解释：

- 加 **V-JEPA 2**（E13）→ 排除"这是去噪训练的产物"（它不去噪、不重建、无 VAE）
- 加 **ViT-H**（E13）→ 排除"只是小模型才会"
- 加 **HunyuanVideo**（E14）→ 排除"与 block 拓扑/文本条件形式有关"（唯一双流→单流串联）
- 加 **Wan2.2 双专家**（E17）→ 排除"与专家专精的噪声区间有关"（架构/数据/规模全固定）
- 补 **LikePhys 侧**（E15 附录）→ 排除"只在 IntPhys 2 的编辑方式下成立"

**计数口径**：`results/D2_TALLY.json`（`scripts/audit_d2_count.py` 生成）。
格数 ≠ 独立单元数：同一层内 flat/timeavg 是同一次提取的两种读出、同一专家的两层共享一次提取，
都不能算独立复现。**引用时必须同时给两个数。**

### 1.1 D2 还没覆盖的（写 Limitations 时要列）

1. **两个数据集都是"合成编辑"**：IntPhys 2 是渲染 + 物理参数改动，LikePhys 是仿真 + 扰动。
   **真实世界视频**一个都没测。这是"广泛性"的最大缺口，且**再加模型也补不上**。
2. **读出只有线性（logistic）**。E8 §5.3.2 测过一个偏弱的 MLP（自评"偏弱对照"），
   E11（更强的非线性读出）仍未做。
3. **只有视觉**，没有音频/多模态。

## 2. D1 为什么不能说"越来越广泛"

D1 这一轮有**四处被动**，方向都是收窄：

### 2.1 E12 否证了 E8 的解释（不是小修正，是删掉一个机制）

E8 §14.3 说 LTX 弱"最可能是 token 预算（1792）"。E12 在同一模型内把 token 推到 12800：

```
1792 → 0.5506 | 3328 → 0.5480 | 6400 → 0.5519
9472 → 0.5304 | 11008 → 0.5397 | 12800 → 0.5308
斜率 −0.0096 / e-fold，95% CI [−0.0308, +0.0088]
```

**平的，甚至略降。** 而且维度受控的 timeavg 口径（每档 2048 维）也是平的 → 不是容量问题。

→ 现在的解释是**架构**（32× 空间压缩 + patch=1），不是预算。这是**换了一个机制**，不是加个限定。

### 2.2 E16 取消了整个"排序"类主张（最实质的一次收窄）

E16 把 probe 的 CV 划分从 1 个扩到 6 个，测了 E8 的全部 12 个格：

| 相邻一对（同数据集）| D1 差距 | 各自 sd | 可排序？ |
|---|---|---|---|
| CogVideoX-2b vs 5b @ LikePhys | **+0.2 pp** | 1.84 / 1.96 | ❌ |
| CogVideoX-2b vs Mochi @ IntPhys 2 | +2.4 pp | 3.24 / 2.51 | ❌ |
| Wan2.1-14B vs 1.3B @ IntPhys 2 | +4.0 pp（≈1.98 个合并 sd，**两分布有重叠**）| 2.07 / 1.98 | ⚠️ 边界，不能按 E8 原文的"明显"写 |

→ **E8 §14.4 那句"D1 的数值与规模有关（14B 的 99.1% **明显**高于 1.3B 的 91.2%）"必须降级。**
  精确数字：单划分报的是 7.9 pp，六划分均值只差 **4.01 pp**（1.98 个合并 sd），
  且 14B 的范围 [93.7, 99.3] 与 1.3B 的 [91.2, 96.5] **有重叠**。
  → 正确的写法是"**方向上可能有规模效应，但按单划分数字会高估一倍，且不足以支持明确断言**"，
  而不是"与规模有关"或"无关"中的任何一个。
→ **pass/fail 判定本身稳**（11/12 稳定，唯一翻转的 LTX@IntPhys2 本来就被 T10 排除在判定之外）。
→ 这是好消息也是坏消息：**判定硬，比较软。**

### 2.3 E13/E15：非生成式落在阈值上（不是通过，也不是不通过）

| 模型 | IntPhys 2 D1 | LikePhys D1 |
|---|---|---|
| V-JEPA 2 ViT-L | 92.9% | **49.4% ± 2.29**（5/6 划分低于 50%）|
| V-JEPA 2 ViT-H | 83.2% | **54.1% ± 3.40**（1/6 划分低于 50%）|

**IntPhys 2 上规模越大越弱，LikePhys 上规模越大越强——方向相反。** 两处各只有一个规模对，
都不足以支持任何方向性主张。

→ E8 §14.5 的"真正决定 D1 的是数据集，不是 backbone"要改成
  **"主要是数据集，但训练目标的影响未被排除"**。

### 2.4 E17 是一个 null（但有用）

Wan2.2-A14B 的两个专家（同架构、同数据、同规模，只差噪声区间）：
D1 = 99.1% / 99.1%，差 **0.06 pp**，比 probe 噪声（2.51 pp）小两个数量级。

→ 排除了一类解释（专精的噪声区间不影响 D1），但**没有增加"广泛"**，只是收窄了不确定范围。

## 3. 这一轮暴露的两个方法学问题（已修，且应长期遵守）

### 3.1 probe 依赖 BLAS 线程数（新发现的复现漏洞）

同一批特征、同一个 probe，只改线程数：

| threads | cogvideox2b@IntPhys2 random AUC |
|---|---|
| **4** | **0.5212671690375497**（与 E8 逐位相同）|
| 1 | 0.5213261335383826 |
| 3 | 0.520435 |

LBFGS 在 300×300 Gram 的病态问题上不收敛到唯一点。**3 线程与 4 线程差 0.5 个百分点**，
比 E17 要测的差值（0.06 pp）大一个数量级。

**规矩**：任何引用 probe 数值的报告必须记录 `threads`；**同一张表内必须同线程数**。
E8 当时恰好是 4（用 E16 的 12/12 逐位复现反推出来的），但**没有记录在案**，已补进 manifest。

### 3.2 手工计数三次出错

D2 的总格数我手工数错过 **三次**（13 → 20 → 28），D1 错过一次（13 → 18）。
现在两个数**只能**从 `results/D1_TALLY.json` / `results/D2_TALLY.json` 引用，
由 `scripts/audit_d1_count.py` / `audit_d2_count.py` 从交付 JSON 数出。

### 3.3 新增的自动审计

`scripts/audit_reports.py`：逐份报告检查每个小数/百分比能否在 JSON 里找到来源。
**7 份报告全部通过**（26 项跨任务引用显式登记理由）。
E8 的 4 个历史遗留数字（如 §13 的 0.4483）登记为已知缺陷，**没有手改已交付内容**，
而是追加 §16/§17 说明。

## 4. 所以现在能写什么、不能写什么

### 能写（有 N 个独立单元的支撑）

1. **D2 跨范式成立**：28 格 / 19 单元 / 6 族，含非生成式，零例外。
2. **D1 是数据集依赖的**：IntPhys 2 上 18 pass + 1 不可解读；LikePhys 上 8 fail + 2 落在阈值。
3. **D1 对 probe 划分稳健**（判定层面）：11/12 格在 6 个划分下判定不变。
4. **token 预算不是 LTX 弱信号的原因**（E12 直接否证）。

### 不能写

1. ❌ "训练只贡献少数信号" → **只在 LikePhys 上成立**
2. ⚠️ "14B 比 1.3B 好 / 大模型更懂物理" → **不能断言**。差的真实量级是 4 pp、约 2 个 sd、分布重叠；
   单划分的 7.9 pp 高估了一倍
3. ❌ "trained > random > 原始像素"是普适排序 → **HunyuanVideo 上 random 更低**
4. ❌ "非生成式编码器上 D1 也低" → **它压在阈值上，49.4% ± 2.3**
5. ❌ "不是 backbone 的特性" → **要加"训练目标的影响未被排除"**

## 5. 广泛性还能往哪扩（按价值排序）

| 方向 | 为什么值 | 成本 | 能否补"广泛性" |
|---|---|---|---|
| **换数据集的生成方式**（真实视频 / 别的 benchmark）| **最大缺口**。两个数据集都是合成编辑，再加模型也补不上 | 高 | ⭐⭐⭐ |
| **非线性读出**（E11）| 排除"只有线性结论"这条退路 | 零（现成缓存）| ⭐⭐ |
| **剔除饱和场景重算**（E9）| 5/12 场景 `real−random=0`，会拉低全局均值 | 零 | ⭐ |
| **E17 的两个专家各放到自己的噪声区间** | 唯一能把"专精"与"泛化"拆开的设计 | 中 | ⭐ |
| **再加第 7、8 个模型** | **边际价值最低**。上面 5 条轴已逐个排除，再加同类模型只是重复 | 高 | ~0 |

**结论：模型数量已经饱和。真正能增加广泛性的下一步是换 benchmark，不是换模型。**
