> 执行于 2026-09-17，4×RTX 4090（验卡全过，逐算子与 CPU 逐位相同）。

## 0. 结论

| 层级 | 结论 |
|---|---|
| **零档闸门** | ✅ **通过**，max drop **0.0005** vs 门槛 0.2486 —— 管线本身几乎不可见 |
| **预注册判据（real AUC）** | ❌ **H4 不被支持**：最大降幅 0.0200 = **0.16×** 地板，仅 2/7 场景有下降（需 ≥5） |
| **单向性（§4.2 强制）** | ⚠️ **这不是对 H4 的反驳**：档 3 的 128 px 只有真实运动 479 px 的 **27%** |
| **exploratory 敏感度检验** | 🔴 **AUC 的 null 是天花板假象**：d′ 在 **7/7** 场景单调下降，L3 仅保留 **0.754** |

**一句话**：按预注册读出量 S4 判为「无衰减」，
但该读出量在此区间**饱和失灵**——换一个不饱和的读出量，7/7 场景都出现了单调衰减。

## 1. 零档闸门（硬规则①，先跑先判）

强度 0 = 恒等变换但**完整走一遍 warp + crop + 上采样管线**。

| 场景 | real AUC | 相对 S3 baseline 1.0000 的降幅 |
|---|---|---|
| ball_drop / cloth_drape / faucet / fluid / pendulum / river | 1.0000 | **0.0000** |
| pyramid | 0.9995 | **0.0005** |

**max drop 0.0005 vs 门槛 0.2486（= 2× 置换地板 sd 0.1243）→ 通过。**

意义：47.3% 面积的裁剪 + 1.4545× 上采样**对 probe 几乎不可见**，
因此后续各档的任何变化都可归因于相机运动，而不是重采样管线。

## 2. 实现与几何（A.2 / A.3 第 3 条）

### 2.1 单次重采样

crop 缩放、旋转、平移**合成进同一个 `grid_sample`**：

```
source_norm = S · R(θ_f) · (u, v) + T_f       S = 352/512 = 0.6875
```

A.2 要求「bilinear，align_corners=False」且「避免引入第二种重采样核」。
若按 warp → crop → resize 分三步做，会叠三次插值核，模糊量远超相机运动本身。

### 2.2 轨迹约定

`ramp(f) = f/48 − 0.5`（**居中**），使**相对首帧的位移**跨满目标位移量
（A.5 定义档位用的正是「累计位移（最大偏移）」），而 `|T|` 本身只到 CUM/2。
居中使同样位移量下所需的裁剪**减半**。

### 2.3 实际裁剪比例与有效视场（A.3 第 3 条，必报）

| 项 | 值 |
|---|---|
| 裁剪尺寸 | **352 × 352**（原 512 × 512） |
| 线性比例 | 0.6875 |
| **有效视场（面积）** | **47.27%** |
| 上采样倍率 | 1.4545× |
| **裁剪对所有档统一** | ✅ 按最大档（档 3）取齐 |
| **填充像素数** | **0**（全档、全 clip） |

裁剪量由几何硬约束反推：`S·(|cosθ|+|sinθ|) + |T|_∞ ≤ 1`，
档 3 代入得 `S ≤ 0.716`，取 352 px（S=0.6875）留 8.6 px 余量。
`build_grid` 对每个采样坐标做断言，**越界即抛异常**，所以「零填充」不是承诺而是被强制的。

### 2.4 几何自检（跑数前）

`s4_camera_selftest.py` 七组全过：

- 四档位移量与 A.5 冻结值一致（31.75 / 63.50 / 127.01 px，含抖动容差）
- 全档 × 10 subgroup 的 `max |grid coord| = 0.9665 ≤ 1.0`
- 同 (scenario, subgroup) 重复调用**逐位相同**；换 subgroup / 换场景轨迹不同
- 档 0 的 grid 逐帧相同，且**恰好等于纯中心裁剪**
- 竖直边缘在档 3 下移动 **183 out-px**，预测 183.3 —— 位移量对得上
- 恒定灰度图 warp 后 `min == 0.5`，**无填充零值**

## 5. EXPLORATORY：AUC 的 null 是天花板假象

> **状态：非预注册，按硬规则⑤ 标注 exploratory，不混入主结论。**

### 5.1 为什么要做这个检验

`PREREG.md` §4.2 选 real AUC 作主读出量的理由是
「baseline = 1.0000、sd = 0.0000，任何下降都可测」。

**对一个有界的秩统计量，这个推理是反的**：AUC = 1.0 正是**饱和点**。
只要两类决策值分布尚未真正交叠，间隔缩小多少 AUC 都纹丝不动。
5/7 场景返回的降幅恰好是 **0.0000**，这本身就是饱和的征兆。

### 5.2 换一个不饱和的读出量

d′ = (mean(s|y=1) − mean(s|y=0)) / pooled_sd(s)，
在**完全相同的折、相同的降采样、相同的 C 选择**下于留出折上计算。

**real 的 d′（相对 L0）**

| 场景 | L0 | L1 | L2 | L3 |
|---|---|---|---|---|
| ball_drop | 1.000 | 0.887 | 0.902 | **0.844** |
| cloth_drape | 1.000 | 0.879 | 0.890 | **0.790** |
| faucet | 1.000 | 0.769 | 0.731 | **0.703** |
| fluid | 1.000 | 0.853 | 0.863 | **0.727** |
| pendulum | 1.000 | 0.854 | 0.660 | **0.632** |
| pyramid | 1.000 | 0.946 | 0.932 | **0.877** |
| river | 1.000 | 0.752 | 0.708 | **0.706** |

**7/7 场景下降，均值保留 0.754**（即类间间隔损失约 **25%**），且基本单调。

而同期 real AUC 在其中 5 个场景是**恒定 1.0000**。

### 5.3 对 §4.2 margin 解读的更正

同样算 random 的 d′：

| | L3 保留比例（均值） | 最小 |
|---|---|---|
| real | **0.754** | 0.632 |
| random | **0.656** | 0.207 |

两者差 0.098 < 0.10。**去掉天花板后，两个 backbone 的衰减幅度相当**，
所以 §4.2 的「训练过的 backbone 对相机运动鲁棒」**不成立**，
那是 real 被钉在 1.0000 造成的假象。**§4.2 的 margin 方向性解读作废。**

### 5.4 这一节的地位

- **不改变**主判定：按预注册读出量，S4 判为 H4 不被支持。
- **但削弱该 null 的证据力**：主读出量在此区间已被证明不敏感。
- 同时**仍受 27% 量级限制**，所以 d′ 的衰减也不能反过来当作 H4 成立的证据。

## 6. 给负责人的两点

1. **读出量修订引入了一个未预料到的问题。** 本轮把主读出量从 margin 改成 real AUC，
   理由是「baseline sd = 0.0000，任何下降都可测」。
   实测表明这个理由对秩统计量是反的：**正因为 baseline = 1.0000，它落在饱和点上，
   是最不敏感的位置**。下次若还要用「饱和场景」作起跑线，
   建议直接用 d′ 或决策值间隔这类无界读出量，并在预注册阶段就写死。

2. **我的一次过度解读已自我更正。** §4.2 的「margin 增大 ⇒ 训练网络更鲁棒」
   是我先写出来的，补了 random 的 d′ 之后被自己推翻，已在 §5.3 明确作废并保留推理痕迹。
