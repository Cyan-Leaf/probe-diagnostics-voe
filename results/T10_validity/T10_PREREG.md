# T10 预注册 — 协议 validity 的判据

> **写定于 2026-09-19，在任何构造案例被评测之前。**
> 依据 `PROTOCOL_VALIDITY.md` §2/§4、`handoff/HANDOFF.md` T10.2/T10.3、硬规则①。
> 冻结后偏离按硬规则④标注 exploratory。

## 0. 为什么要有这份文件

协议 validity 的三类证据里，B（最小性消融）用的是已有数据、没有自由度；
**A（构造效度）与 C（充分性边界）是新造数据，有自由度，因此判据必须先写死** ——
否则「四个案例全部判对」这种结论毫无意义（可以反复调阈值直到对）。

## 1. 共同设定（冻结）

| 项 | 值 |
|---|---|
| 样本结构 | 沿用 LikePhys physics 组：**120 valid + 630 violation = 750**，group = `(scenario, subgroup)` |
| probe 协议 | 与全项目一致：`StandardScaler` → L2 logistic，C 由训练折内 3 折 CV 选，外层 `GroupKFold(5)` |
| 特征维度 | **256**（足够承载构造信号，又远小于 n，避免 p≫n 带来的额外方差） |
| 随机源 | 全部 `numpy.random.default_rng(seed)`，seed 写在各案例内，**结果可逐位复现** |
| 读出量 | AUC **与** d′ 同报（D6 要求：构造案例里 A4 故意饱和，必须有无界量） |
| 地板 | 定义 A（seed-spread）：每个案例用 3 个构造 seed，报 seed 间 sd |

**关键约束**：所有案例的「真相」由构造方式**定义**，不由协议判定。
协议只是被测对象。

## 2. 证据 A：四个构造案例（判据写死）

### A1 阳性对照 —— 确实编码物理

**构造**：`x = [s·y + ε, 噪声维度…]`，其中 `y` 是真实物理标签、`s` 控制信噪比。
物理信息**只**存在于前若干维，且与标签线性相关。
**同一构造同时生成 real 与 random 两侧**：real 侧 `s = s_real`，random 侧 `s = 0.25·s_real`
（模拟「随机初始化网络仍能拿到部分信号，但明显更少」）。

> 这里的 `0.25` 是**刻意选的**：它使 D1 的训练增量占比落在 50% 以上（应通过），
> 而不是让 random 完全无信号（那样 D1 会过于容易通过）。

**真相**：表征确实编码物理。

**协议应给出**：D1–D6 **全部通过**。

| 检查 | 通过标准 |
|---|---|
| D1 | 训练增量占比 ≥ 50% |
| D2 | AUC(外观对照) < AUC(物理) |
| D3 | 不饱和：real AUC < 0.99 |
| D4 | 效应 > 2× seed-spread 地板 |
| D5 | 两种读出（AUC / d′）方向一致 |
| D6 | baseline 不在边界（0.51 < AUC < 0.99），故有界量可用 |

### A2 阴性对照 —— 完全不编码物理

**构造**：特征 = **颜色直方图式**的量，与物理标签**统计独立**，
但与一个「外观组」标签完全相关（模拟只含外观信息的表征）。
具体：`x = [c·a + ε, 噪声…]`，`a` 是外观标签，**`y` 不进特征**。

**真相**：完全不编码物理。

**协议应给出**：**D1 或 D2 必须失败**。
- 预期 D1 失败（real 与 random 都拿不到物理信号 → 增量占比无意义/极低）
- 预期 D2 失败（外观任务远高于物理任务）

**判据**：至少一项失败即算判对；两项都通过则**协议判错**。

### A3 混合对照 —— 部分真实 + 部分伪信号

**构造**：A1 的物理维度 **+** 一组与「是否被编辑」完全相关的维度
（编辑痕迹），比例由 `artifact_scale` 控制。

**真相**：物理确有编码，但同时存在可被 probe 利用的编辑痕迹。

**协议应给出**：**D2 失败、D1 通过**。

**判据**：必须同时满足；若 D2 通过（即没检出编辑痕迹）则**协议判错**。

### A4 饱和对照 —— 数字虚高

**构造**：把 `s` 提到使任务几乎完美可分（目标 real AUC ≥ 0.999）。

**真相**：AUC 数字虚高，已无分辨率。

**协议应给出**：**D3 或 D6 必须触发**。
- D3 触发条件：real − random < 2× 地板（饱和判定）
- D6 触发条件：real AUC ≥ 0.99（有界量处于边界 → 禁用 AUC 作主读出量）

**判据**：至少一项触发即算判对；两项都不触发则**协议判错**。

### 总判据（`PROTOCOL_VALIDITY.md` §2 原文）

> 四个案例中，协议的判定必须**与真相全部一致**；
> 若有任一案例判错 → **该项检查的判据阈值需要修正，并如实报告是哪一项、怎么修的。**

**本文件补充一条**：修正阈值后**必须重跑全部四个案例**，
并在报告中同时给出修正前与修正后的两套结果，**不得只报修正后的**。

## 3. 证据 C：两条攻击（判据写死）

### C1 相关伪信号

**目标**：构造一个伪信号，使其
**依赖训练**（过 D1）、**与外观无关**（过 D2）、**不饱和**（过 D3/D6）、
**两种读出一致**（过 D5），但我们**知道**它不是物理。

**构造思路**：让伪信号是一个与物理标签高度相关、但**语义上不是物理**的量 ——
例如「该 clip 属于哪个 subgroup 的编号奇偶性」若恰好与标签相关，
或更现实的：**渲染批次标识**。
本轮采用：注入一个 `batch_id` 维度，其分布与标签相关（模拟数据集构造泄漏），
并让 random 侧拿不到它（模拟「依赖训练」）。

**成功判据**：**六项全部通过**，而真相是「不编码物理」。

### C2 流程性混淆（D2 测不到的那类）

**目标**：违反与合法视频在**采集/渲染流程**上系统性不同，
而这种差异**既不是外观、也不是复杂度**，因此 D2（外观对照）与 E4（复杂度）都测不到。

**构造**：注入一组维度，模拟「两类视频用了不同的编码器/渲染 pass」——
对**物理标签**完全可分，但与**外观标签**独立、与**复杂度代理量**独立。

**成功判据**：六项全部通过。

### C 的总判据

| 结果 | 后续动作 |
|---|---|
| C1 或 C2 任一成功 | **把 `minimal sufficient` 改为 `minimal necessary`**，并写明协议测不到哪类混淆 |
| 两条都失败 | 报告「在这两条攻击下未能骗过协议」，**不得因此声称协议充分**（只能说这两条没成功） |

**禁止**（HANDOFF 原文）：为了保住「充分」这个词而放弃这项检验，
或把失败的攻击说成成功。

## 4. 证据 B：最小性消融（无自由度，但记录做法）

对 12（LikePhys）+ 5（IntPhys 2）= **17 个单元**，逐项移除一项检查，
统计**被漏判的单元数**。

「漏判」的定义（冻结）：
**在移除该项后，一个本应被判为「结论不可信」的单元，变成了「结论可信」。**

数据全部来自已有结果文件，**不新跑任何实验**，故无阈值自由度。

**额外必做**（HANDOFF 明确要求）：用数据显式区分 D3 与 D6 ——
**在已剔除饱和单元的子集上**对比 AUC 与 d′，
证明「只做 D3（数据层面剔除）不足以替代 D6（读出量层面）」。
