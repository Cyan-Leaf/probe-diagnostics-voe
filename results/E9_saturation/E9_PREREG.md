# E9 预注册：剔除饱和场景后重算

**写于任何 E9 计算之前：2026-10-29**

---

## 1. 要修的问题

`NEXT_STEPS_AND_DIVISION.md` §1 记的是：

> **E9** 剔除饱和场景后重算主结果｜中。12 场景中 5 个 `real−random=0`，会拉低全局均值｜零算力

具体机制：LikePhys 的 12 个场景里，有 5 个场景中**训练 DiT 与随机初始化的 AUC 恰好都到 1.000**
（差值 0.00）。这些场景对 `trained − random` 这个**分子**贡献 0，
但对**分母** `trained − 0.5` 有贡献 —— 于是全局 D1 被系统性地压低。

**这不是噪声，是可预测的偏差。** E9 要量化它：剔除饱和场景后 D1 变多少。

## 2. 定义（写死，不许事后调整）

**饱和场景**：在参考格上满足 `AUC_real ≥ 1.000 − δ` **且** `AUC_random ≥ 1.000 − δ`，
其中 `δ = 1e-9`（即**严格到 1.000**，不是"接近"）。

**为什么 δ 这么严**：AUC = 1.0 是**有界秩统计量的饱和点**（`PROTOCOL_VALIDITY.md`
的 D3/D6：饱和区禁用有界统计量）。用 `δ = 0.01` 之类会把"0.995"也算饱和，
那就不再是"统计量触界"而是"信号强"，两者的处理完全不同。

**参考格**：`L16 / t=600`（与 E8/E12–E17 一致），Wan2.1-1.3B@LikePhys
（`NEXT_STEPS` 说的"主结果"就是这个格）。

## 3. 两个总体量，都要报

| 量 | 定义 | 为什么两个都要 |
|---|---|---|
| **池化 D1** | 用**全部 clip** 重算 AUC（real 与 random 各一次），再算 `(A−B)/(A−0.5)` | 这是 E8 各处用的口径，可与已交付数字直接比 |
| **逐场景 D1 的均值** | 每个场景单独算 AUC → 单独算 D1 → 12 个取均值 | 这是"饱和场景拉低均值"这个说法**字面上**指的算法 |

**这两个不是同一个数**，而且剔除饱和场景对它们的影响方向可能不同：
- 池化：剔除会让分母变小、分子变大 → D1 **上升**
- 逐场景均值：删掉 5 个 0 值 → 剩余 7 个的均值 **上升**

→ 报告必须分开写，**不得**把其中一个说成"主结果"。

## 4. 判据

**Q1**：剔除饱和场景后，池化 D1 是否越过 50% 阈值？

- **仍 < 50%** → D1 判定**不因饱和场景而变**，E8 的结论稳
- **≥ 50%** → **E8 在 LikePhys 上的 D1 判定是被饱和场景压低的**，
  这是**会改写结论**的结果，必须写进主文

**Q2**：变化幅度 `ΔD1 = D1(剔除后) − D1(全部)` 是多少个百分点？
- 报数值 + 与 E16 的 probe 划分 sd（2.51 pp）比较
- `|ΔD1| < 2.51` → 变化在噪声内；`≥ 2.51` → 是实质变化

**Q3（必报，防误读）**：剔除的 5 个场景是**哪 5 个**，它们的 `n` 是多少。
若剔除掉的 clip 数占比很大（> 30%），那么"剔除后"的结果**样本量骤减**，
其不确定性要单独说清楚，不能当成更干净的估计。

## 5. 明确不做

- **不改 D1 的定义**（分子分母都不动）
- **不用剔除后的结果替换** E8 的交付数字（红线：不手改已交付）
- **不做"剔除后跨模型比较"**：不同模型的饱和场景集合不同，剔除后不可比
- 不把逐场景均值当成主结果
