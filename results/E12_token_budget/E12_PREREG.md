# E12 预注册：token 预算是否为 LTX 弱信号的原因

**写于任何提取之前：2026-10-28**
上游协议：`PREREG.md` D1 / D2 + `results/E8_second_backbone/E8_PREREG.md`
参考格沿用：`layer 16 / t=600`（与 E8 一致，不重新定义）

---

## 1. 要回答的问题

E8 §14.3 / §15 留下一个**无法判定**的格：LTX-Video-0.9.5 在 IntPhys 2 上

- real AUC **0.5506**，random 0.5261，地板 0.0150 → D1 = **48.5%**，T10 判 **NOT interpretable**
- 相邻层 L15 的 D1 是 60.7%（pass），**同一模型相邻两层判定翻转**

E8 给的解释是「LTX 的 token 预算只有 1792，其他模型 9216–13312」，但**报告自己写明这是候选解释、不是结论**，因为 token 预算与架构完全混杂：只有一个模型有 1792 个 token，也只有一个模型是 32× 空间压缩的 VAE。

**E12 用一个模型内部的变化把这两个因素分开。** 不动权重、不动架构、不动 probe，只改 token 预算，看 real AUC 和 D1 是否随之变化。

## 2. 为什么这个设计能分开混杂

token 预算在同一模型内部可以只通过**输入几何**改变：

| 改什么 | token 数怎么变 | 引入的信息变化 |
|---|---|---|
| 只改帧数 F | `F_lat × (S/32)²`，`F_lat = (F-1)/8+1` | 时间分辨率变化 |
| 只改边长 S | `F_lat × (S/32)²` | 空间分辨率变化 |
| 两者都改 | 见下表 | 两者都变 |

**关键能力：LTX 可以被推到 13312 token，正好等于 CogVideoX / Wan 的主格。** 于是有两组"同 token 数、不同架构"的对照点，E8 缺的正是这种点。

### 2.1 LTX 的 token 梯子（S=512 固定，只改 F）

| F | F_lat | token | 与 E8 的关系 |
|---|---|---|---|
| 49 | 7 | **1792** | **E8 主格，已存在，不重跑** |
| 97 | 13 | 3328 | 新增 |
| 193 | 25 | 6400 | 新增 |
| 289 | 37 | 9472 | 新增 |
| 337 | 43 | 11008 | 备用（如果 289 已在平台） |
| 393 | 50 | 12800 | 新增 |

IntPhys 2 的 clip 有 **636 帧**，所以以上全部是**真实的时间下采样**，不是插值凑数。
（E8 的做法一直是"在整段 clip 上均匀取 F 帧"，这里沿用，见 §4.2 的代价说明。）

### 2.2 CogVideoX-2b 的 token 梯子（F=49 固定，只改 S）

patch_size=2，8× 空间、4× 时间压缩，`F_lat = 13`：

| S | token | 与 E8 的关系 |
|---|---|---|
| 512 | **13312** | **E8 主格，已存在，不重跑** |
| 384 | 7488 | 新增 |
| 256 | 3328 | 新增 |
| 192 | 1872 | 新增（≈ LTX 主格，反向对照） |

### 2.3 交叉点（这是 E12 的主结果）

| token ≈ | LTX | CogVideoX-2b | 能回答什么 |
|---|---|---|---|
| **~1800** | 512/49 = 1792（已有） | 192/49 = 1872（新） | **CogVideoX 掉到 1792 token 时会不会也塌到 0.55？** |
| **~3300** | 512/97 = 3328（新） | 256/49 = 3328（新） | 中间点 |
| **~13300** | 1024/97 = 13312（新） | 512/49（已有） | **LTX 升到 13312 token 时会不会升到 0.64？** |

后两行是判定的关键。第一行是它的镜像。

## 3. 判据（**跑数前写死**）

三个问题，各自有独立的判据，不合并成一个总分。

### Q1（主）：LTX 的 real AUC 是否随 token 预算上升？

- **统计量**：`AUC_real(token)` 在 §2.1 的 6 个点上（含已有的 1792）
- **判据**：对 `log(token)` 做加权最小二乘斜率，**bootstrap over scenes**（IntPhys2 用 `SceneIndex`，1000 次重采样）给 95% CI
  - **PASS-token**：斜率 CI 下界 > 0 **且** `AUC_real(13312) − AUC_real(1792) ≥ 0.05`
  - **FAIL-token**：斜率 CI 上界 < 0.01/每 e 倍 token
  - **其余**：`INCONCLUSIVE`，照实报

  两个条件都要满足才判 PASS，因为"统计显著但幅度微不足道"在这个项目里已经出现过（T12 的 margin 讨论）。

- **反向对照（必做，否则无法区分"token 多"和"信息多"）**：同一批 token 数下，`AUC_random` 必须**不**以同样斜率上升。定义
  `ΔΔ = slope(AUC_real) − slope(AUC_random)`，**ΔΔ 的 CI 下界 > 0** 才算 Q1 通过。
  CogVideoX-2b 的 §10 网格里 random AUC 在 6 层 × 6 个 t 上几乎恒为 0.51–0.52，所以这是可检验的。

- **知识边界**：`raw pixel` 下界必须一并报。若 raw pixel 也随 token 预算上升，说明"更多帧 = 更多可见信息"，那么 AUC_real 的上升**不能**归因于 DiT 的 token 预算，Q1 只能报 INCONCLUSIVE。这一条是为了防止把"看得更清楚"写成"表征更好"。

### Q2：跨架构同 token 对照

- 在 **~1800** 与 **~13300** 两个 token 档上，比较 LTX 与 CogVideoX-2b 的 real AUC
- **判据**：在 ~13300 档，`|AUC_ltx − AUC_cog| < 0.05` → 说明**架构不重要、token 预算重要**；
  若 `AUC_ltx` 仍比 `AUC_cog` 低 > 0.05，说明**架构有独立贡献**（LTX 的 32× VAE 或 patch=1 是另一回事）
- 这一条是**双侧**的，不做"哪个更好"的方向性主张

### Q3：D1 的可解读性是否随 token 预算恢复

- 每个 token 档都算 D1 与 T10 门槛（`效应 > 2×地板` 且 `AUC_real − 0.5 > 2×地板`）
- **判据**：给出"从哪个 token 档开始 D1 变可解读"的区间估计，**不要求**某个特定档通过
- **明确不做的**：不在多个层里挑一个让 D1 最好看的层。层固定 L16 + Lrel 两个格，与 E8 §15 同口径

## 4. 必须先声明的偏离与代价

### 4.1 帧数不同 ⇒ 看到的时间跨度不同，这是固有的

E8 全部 backbone 都用"整段 clip 均匀取 49 帧"。E12 的 LTX 梯子改帧数，等于改变了模型看到的时间跨度：

- F=49 覆盖 636 帧的全程，相邻采样帧间隔约 13 帧
- F=393 覆盖同样的全程，相邻采样帧间隔约 1.6 帧

**这既是 token 预算的变化，也是时间保真度的变化，两者无法完全分开。**
缓解办法只有一条：**同时报 CogVideoX 的空间梯子**（§2.2，F 固定 49，只改 S）。空间梯子上时间保真度不变，若两条梯子的斜率同号同量级，则"token 预算"这个共同因素成立；若只有时间梯子有斜率，则结论必须写成"时间保真度"而不是"token 预算"。

**这个区分是 E12 的设计核心，不是补丁。**

### 4.2 空间梯子在 192 上会损失细节，不可逆

CogVideoX 的 S=192 是把 512 原生 clip 降采样到 192。这与 LTX 的 token 少**不是同一件事**：一个是主动丢信息，一个是架构本来就读不到那么多。
→ 因此 **192 这一档只用于 Q2 的交叉对照，不参与 Q1 的斜率拟合**。斜率拟合只用 §2.1 的时间梯子。

### 4.3 1024 的 LTX 是从 512 上采样，不是原生 1024

IntPhys 2 原生 512×512。S=1024 的 token 数是真的，但每 4 个 token 只对应 1 个真实像素。
→ **1024 档只用于 Q2**（补齐 13312 token 的交叉点），**不参与 Q1 斜率拟合**。
→ 若 1024/97 与 512/393 在同一 token 数下差 > 0.03，报告必须写明两者不等价。

### 4.4 时间梯子同时改变特征维度（**必须双口径报告**）

E8 的特征是"每个 latent 帧一个 D 维向量"，摊平后维度 = `F_lat × D`。改帧数就改了 `F_lat`：

| 配置 | F_lat | 特征维度（D=2048）|
|---|---|---|
| LTX F=49 | 7 | 14336 |
| LTX F=193 | 25 | 51200 |
| LTX F=393 | 50 | 102400 |

所以时间梯子上 **token 预算与 probe 输入维度同时变化**。维度更高不一定更好（n≈1012、5 折分组 CV 下有容量风险），但也可能刚好补上 LTX 原本偏小的容量。这是**真实的混杂**，不是可以忽略的细节。

**双口径，都报，判定取交集：**

- **口径 A（与 E8 一致）**：`F_lat × D` 摊平。这是能和 E8 的 1792 主格直接比的那个数。
- **口径 B（维度受控）**：在时间维上再取均值，得到 `D` 维，**所有 rung 维度相同**。只有这个口径能单独归因于 token 预算。

**Q1 的判定规则据此收紧**：口径 A 通过**且**口径 B 通过才算 `PASS-token`；只有一个通过则报 `INCONCLUSIVE` 并写明是哪个口径。
先验预期（写在这里以免事后合理化）：若 LTX 的弱信号是容量不足，口径 B 会**平**而口径 A 会上升；若真是 token 预算，两个口径都会上升。

### 4.5 CogVideoX 的空间梯子维度天然恒定，因此它是**更干净**的那条

E8 的池化是"每 latent 帧一个 D 维向量"，CogVideoX 的 `F_lat` 恒为 13，
所以 S=512/384/256/192 四个点上**特征维度全是 13×1920 = 24960**，只有 token 数变。

→ 空间梯子上"token 预算"与"probe 输入维度"**不混杂**，不需要口径 B。
→ 代价是它同时改变了空间细节（§4.2 / §4.3）。所以两条梯子各有各的混杂，**必须并列**：
   - 时间梯子：混杂 probe 维度（口径 B 可解）
   - 空间梯子：混杂空间细节（无法解，只能靠"两条梯子同号同量级"间接支持）

### 4.5 不做的事

- 不改 `PREREG.md` 的阈值，不改 probe，不改 random 初始化规则（沿用 `_init_norm_aware`）
- 不重跑已有的 1792 / 13312 主格
- 不因为某一档好看而改参考层或参考 t
- 不把 E12 的结论外推到 LikePhys：LikePhys 只有 60 帧，`F_lat` 上限是 8，**时间梯子做不出来**。
  E12 **只做 IntPhys 2**，LikePhys 的 LTX 格保持 E8 原样并在报告里说明原因

## 6. 提取量（先算清再跑）

每个 (模型, 几何, weights, variant) 是一次全量提取：

| 项 | 数量 |
|---|---|
| LTX 时间梯子 | 5 个新几何（97/193/289/337/393 帧）× 2 weights × (plain 1012 + cj 506) |
| CogVideoX 空间梯子 | 3 个新几何（384/256/192）× 2 weights × (plain 1012 + cj 506) |
| LTX 1024 交叉点 | 1 个几何（1024/97 帧）× 2 weights × (plain + cj) |

= 9 个几何 × 2 × 1518 = **27324 次单 clip 提取**，每次 3 个 feature seed。
按 E8 的实测速度（LTX 512 约 0.86 s/clip，CogVideoX 512 约 2.75 s/clip，
两者都含 3 个 seed × 1 个 t），**4 卡 B200 上约 3–5 小时**。

**中途可停**：records 按 clip 落盘，已存在的跳过；shard 可重入。
