# E12 — token 预算能否解释 LTX 的弱信号

生成：2026-10-28　·　协议：`PREREG.md` D1/D2 + `results/E12_token_budget/E12_PREREG.md`

数字出处：`E12_cells_ltx.json`、`E12_cells_cogvideox2b.json` 给逐格原始值，
`E12_verdict.json` 给判定与 bootstrap CI。

---

## 1. 结论先行

**E8 §14.3 那个候选解释被否掉了。**

E8 写的是「LTX 的 real AUC 只有 0.5506，可能是 token 预算只有 1792 造成的（其他模型 9216–13312）」，并明确标注这是**候选解释而非结论**。E12 在同一个模型内部把 token 预算从 1792 推到 12800（7.1 倍），real AUC **没有上升，反而略降**：

| token | 1792 | 3328 | 6400 | 9472 | 11008 | 12800 |
|---|---|---|---|---|---|---|
| real AUC | 0.5506 | 0.5480 | 0.5519 | 0.5304 | 0.5397 | **0.5308** |

斜率 **−0.0096 / 每 e 倍 token**，95% CI `[−0.0308, +0.0088]`。

- **Q1 = `fail_token`**：两个口径（flat / timeavg）的斜率 CI 上界都 < 0.01，按预注册判据为否证
- **Q2 = `mixed`**：在 ~1800 token 档两者几乎相等（LTX 0.5506 vs CogVideoX 0.5844，差 −0.034，在 0.05 容差内）；在 ~13300 档 LTX 明显更低（0.5308 vs 0.6443，差 −0.114）
- **Q3**：LTX 的 D1 在六个档里只有 3328 那一档可解读，**不单调**，所以不能说"token 多了就可解读"

→ **LTX 在 IntPhys 2 上的弱信号不是 token 预算不足造成的。** E8 §14.3 里"最可能的解释是 token 预算"这句话必须删掉。

## 2. 设计：为什么能分开混杂

同一模型内，token 预算只能通过输入几何改变。E12 用了两条梯子，各有各的混杂，**必须并列**：

### 2.1 LTX 时间梯子（S=512 固定，只改帧数）

| F | F_lat | token | 相对 1792 |
|---|---|---|---|
| 49 | 7 | 1792 | 1.0×（E8 主格，复用）|
| 97 | 13 | 3328 | 1.9× |
| 193 | 25 | 6400 | 3.6× |
| 289 | 37 | 9472 | 5.3× |
| 337 | 43 | 11008 | 6.1× |
| 393 | 50 | 12800 | 7.1× |

IntPhys 2 的 clip 有 **636 帧**，所以全部是真实的时间下采样，不是插值凑数。

**混杂**：改帧数同时改了特征维度（`F_lat × 2048`：14336 → 102400）。所以必须双口径报告：
- **口径 A（flat）**：与 E8 一致，`F_lat × D` 摊平
- **口径 B（timeavg）**：时间维先平均，**所有档维度恒为 2048**，只有它能单独归因于 token 预算

预注册 §4.4 事先写明：若弱信号真是容量不足，口径 B 会平而口径 A 会升。**实测两个口径都是平的**，这排除了容量解释。

### 2.2 CogVideoX 空间梯子（F=49 固定，只改边长）

| S | token | 相对 13312 |
|---|---|---|
| 192 | 1872 | 0.14× |
| 256 | 3328 | 0.25× |
| 384 | 7488 | 0.56× |
| 512 | 13312 | 1.0×（E8 主格，复用）|

CogVideoX 的 `F_lat` 恒为 13，所以**特征维度恒定**（13×1920），token 是唯一变化的量。
**混杂**：改边长同时改了空间细节（§4.2 已声明 192 档只用于 Q2 交叉对照，不进斜率拟合）。

## 3. Q1：LTX 的 real AUC 不随 token 预算上升

```
flat    slope_real -0.0096/e-fold  CI [-0.0308, +0.0088]   delta -0.0059  CI [-0.0359, +0.0444]
timeavg slope_real -0.0111/e-fold  CI [-0.0360, +0.0082]   delta -0.0028  CI [-0.0360, +0.0497]
rise (lowest -> highest)            -0.0198  (要求 >= +0.05)
```

三条判据都指向同一结论：

1. **斜率不为正**：两个口径的 CI 上界都在 0 附近（+0.009、+0.008），下界是负的。
2. **幅度远不到门槛**：从最低到最高档变化 **−0.0198**，而预注册要求至少 +0.05。
3. **对照量没有跟着动**：`slope_random` 是 −0.0038 / −0.0083，`delta_slope`（real−random）的 CI 跨零（`−0.036..+0.044`）。即 real 与 random **以同样斜率变化** —— 这本身说明 token 预算在改变"可读性"，但没改变"训练带来的增量"。

**guard 量**：`slope_raw_pixel` 是 +0.0053（flat）/ +0.0013（timeavg），`slope_vae_latent` 是 +0.0044 / +0.0081。两者都接近零，说明**多给帧数并没有让原始像素更容易读出物理**。这一步很重要：如果 raw pixel 也上升，`AUC_real` 的上升就只能解释成"看得更清楚"而不是"表征更好"。

## 4. Q2：同等 token 预算下 LTX 仍然更低

| 档 | 模型 | token | real AUC | 差 |
|---|---|---|---|---|
| ~1800 | LTX | 1792 | 0.5506 | — |
| ~1800 | CogVideoX-2b | 1872 | 0.5844 | **−0.0337** |
| ~13300 | LTX | 12800 | 0.5308 | — |
| ~13300 | CogVideoX-2b | 13312 | 0.6443 | **−0.1135** |

判 **`mixed`**，因为两个档给的方向不一致：

- **低档接近**：1872 vs 1792，差 0.034，在 0.05 容差内 → 在极低预算下，架构差异被压缩
- **高档拉开**：差 0.114 → 预算充足时，**LTX 仍然读不出 CogVideoX 能读出的东西**

**这意味着 E8 §14.3 的完整表述要改成**：不是"LTX 的 token 太少"，而是"LTX 的 `32× 空间压缩 + patch=1` 这个设计，在同等 token 预算下仍然只能读到 0.53–0.55，而 CogVideoX 能读到 0.58–0.64"。

### 4.1 CogVideoX 自己的梯子：确实随预算上升，但那是空间分辨率

```
S=192 (1872 tok)  0.5844   累计 —
S=256 (3328 tok)  0.6120   累计 +0.0277（步长 +0.0277）
S=384 (7488 tok)  0.6365   累计 +0.0521（步长 +0.0245）
S=512 (13312 tok) 0.6443   累计 +0.0599（步长 +0.0078）
```

`slope_real` 是 **+0.0305 / e-fold**，CI `[+0.0061, +0.0512]`（不含零）。
**但这不能读作"token 预算有效"**：这条梯子改的是边长，192 → 512 是 2.7 倍的空间分辨率，
物理违反的像素证据从"看不清"变成"看得清"。`slope_raw_pixel` 在这里也是正的（+0.0053，
与 LTX 那条相同量级但基数不同），说明丢掉的确实是像素信息。

→ **两条梯子的差异本身是 E12 最干净的结论**：同一份 512 原生视频，
LTX 把它压到 1792 token 时读到 0.5506，CogVideoX 把它压到 1872 token 时读到 0.5844；
而 CogVideoX 在 13312 token 时读到 0.6443，LTX 在 12800 token 时读到 0.5308。
**架构（压缩率与 patch 规则）决定能读到什么，token 预算不决定。**

## 5. Q3：D1 可解读性

| token | 1792 | 3328 | 6400 | 9472 | 11008 | 12800 |
|---|---|---|---|---|---|---|
| D1 | 48.5% | 50.3% | 52.3% | 42.1% | 47.9% | 39.2% |
| T10 可解读 | ✗ | **✓** | ✗ | ✗ | ✗ | ✗ |

**不单调**：只有 3328 那一档通过可解读性门槛。原因是分母 `AUC_real − 0.5` 在整个梯子上都是 0.03–0.05，与地板同量级；哪一档恰好"效应略高于 2×地板"具有偶然性。

→ 这直接证实了 E8 §15.3 的警告：**`real AUC < 0.6` 的弱信号区，D1 比值不可靠**。E12 把这句话从"一个层的观察"提升为"六个 token 档的一致现象"。

→ **不能写"增加 token 就能让 D1 变可解读"**。3328 那一档的 50.3% 与 1792 的 48.5% 差 1.8 个百分点，在地板量级内，是噪声。

## 7. 已知限制

1. **只有 IntPhys 2**。LikePhys 的 clip 只有 56–61 帧，LTX 的 8× 时间压缩使 `F_lat ≤ 8`，
   时间梯子根本做不出来（预注册 §4.4 事先声明）。LikePhys 的 LTX 格保持 E8 原样。
2. **1024/97 那个交叉点无法用于 Q1**：IntPhys 2 原生 512，1024 是上采样，
   每 4 个 token 只对应 1 个真实像素。该格只用于 Q2 补齐 13300 档（预注册 §4.3）。
3. **bootstrap 不含重拟合噪声**。CI 是在冻结的折外预测上重采样场景得到的，
   所以它只反映评估单元的抽样噪声，不反映 probe 重训练的不确定性。
   真 CI 会更宽，因此 `fail_token` 的结论**不会被这个方法放宽而变得更容易通过** ——
   方向是保守的，但这一点必须写出来。
4. **空间梯子无法解耦"空间细节"与"token 预算"**。这是为什么 Q1 的判定只依赖时间梯子，
   而 Q2 允许 `mixed`。
